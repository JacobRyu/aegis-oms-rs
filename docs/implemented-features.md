# Aegis OMS — 実装済み機能一覧

## 実装ステータス凡例

| マーク | 意味                           |
|:----:|:------------------------------|
| ✅   | 実装済み・テスト済み              |
| 🔧   | 基盤実装済み（API 提供）、実運用時は呼び出し側で組み込みが必要 |
| ❌   | 未実装（スキーマ定義のみ、または将来対応）|

## 1. 注文管理

| 機能                        | ステータス | 備考                                                     |
|:--------------------------|:--------:|:-------------------------------------------------------|
| Limit 注文 発注              | ✅       | 価格・数量バリデーション、証拠金ロック込み                    |
| Market 注文 発注             | ✅       | 発注時は証拠金スキップ、約定時に証拠金チェック                 |
| 注文キャンセル                | ✅       | Accepted / PartiallyFilled 状態のみキャンセル可能            |
| 部分約定（Partial Fill）      | ✅       | 複数回 `fill_order` 呼び出しで順次約定                      |
| 完全約定（Full Fill）         | ✅       | 最終 fill で `Filled` ステータスへ遷移                     |
| Overfill 防止               | ✅       | 残数量超えの約定はエラー返却                                |
| 注文ステータス遷移バリデーション | ✅       | 不正遷移（Filled → Accepted 等）を検出してエラー             |
| Stop 注文（逆指値）          | ✅       | trigger_price 到達で Market として執行。発注時は PendingTrigger |
| StopLimit 注文（逆指値指値）  | ✅       | trigger_price 到達で Limit として発注                       |
| TrailingStop 注文           | ✅       | best_price から trail_amount 乖離でトリガー。価格追従あり     |
| IOC / FOK の執行ポリシー     | ❌       | 型定義のみ。タイムアウト・即時キャンセルロジックは未実装        |
| 注文一覧取得                 | ✅       | オープン注文（New / Accepted / PartiallyFilled）のみ返却    |

## 11. 既知の制約・設計上の注意点

1. **状態の非永続性**: すべての状態はインメモリ。プロセス終了で消失します。

2. **Market 注文の証拠金**: 約定時に検証しますが、ポジション縮小（クローズ）かどうかを区別せず全数量に対して証拠金チェックを行います。クローズ取引では本来証拠金不要ですが、本実装では保守的にチェックします。

3. **含み損益の更新**: `unrealized_pnl` は `update_positions_pnl(mark_prices)` を明示的に呼び出すことで更新されます。リアルタイムの自動更新はありません。

4. **IOC / FOK**: `TimeInForce` 型は定義済みですが、即時キャンセル・全量約定の執行ロジックは実装されていません。

5. **マッチングエンジン**: 外部マッチングエンジンからの通知を想定した設計です。`fill_order` を直接呼ぶことで約定をシミュレーションできます。

6. **スレッド安全性**: `OrderService` は `Send + Sync` ではありません。マルチスレッド環境で使用する場合は `Arc<Mutex<OrderService>>` でラップする必要があります。

7. **強制ロスカットの執行**: `MarginMonitor::force_liquidate` は Market/IOC クローズ注文を発注しますが、実際の約定は呼び出し元が `fill_order` を呼ぶことで完了します。実環境ではマッチングエンジンとの連携が必要です。

8. **TrailingStop の価格追従**: `best_price` の更新は `CompositeOrderService::on_price_update` 経由のみ。直接フィールドを書き換えないでください。
